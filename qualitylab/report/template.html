Quality Lab · SpireScape

Testing my game like it's production

SpireScape is the multiplayer card battler I'm building. This page reports on a pytest suite that plays it over the network, the same way the browser client does, against a seeded local build and the live public demo.

Claude drafted the tests and reviews every run. I review the tests and decide what gets acted on. Everything below is generated from the run records, so it's only ever as good as the last run.

07

How it's built

The server is C#. The suite never imports it: it speaks the wire protocol from Python, so it tests what a player can actually reach.

Speak the protocol

A Python codec for the server's binary format, checked byte for byte against hand-worked frames and round-tripped by Hypothesis.

Play, don't poke

Tests are written as player steps: talk, gather, craft, fight. Waits are budgeted in server ticks, so one suite runs at 20 ms locally and 600 ms live.

Run in parallel

pytest-xdist gives each worker its own seeded server locally. Live, the fights share one worker because the map has two rats.

Record everything

A small pytest plugin writes each run to JSON: outcome, timing, worker, layer, metrics, and which protocol messages were seen.

Review with AI

Claude summarises the runs and proposes changes. Its claims are checked against the records before they're shown.
